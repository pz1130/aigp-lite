# 测试与治理你自己的 AI Agent

本平台可以对**你自己搭建的** AI Agent 做红队测试和治理。要测得到位,需要从三个不同
的层面去看,每一层对应产品里的一个模块。

## 三层模型

### 1. 嘴 —— 语言行为(实测)

测 Agent **说什么**。把对抗性提问喂进去,对返回的文本打分。这是黑盒、单轮测试:越狱、
毒性、提示注入、偏见、PII 泄露。在 **红队(Red-team)** 模块(`/redteam`)里跑,底层是
Moonshot 引擎。

它**看不到** Agent 调用了哪些工具、做了哪些动作,只看产出的文本。

### 2. 手 —— 工具/动作行为(实测观测)

测 Agent **做什么**。它会不会调用本不该调的工具(OWASP LLM08 —— 过度自主)。文本打分器
看不到这一层,需要工具调用的可观测性。**MCP** 模块(`/mcp`)记录每一次工具调用(调了哪个
工具、谁调的、结果如何),帮你发现越权或过度的工具调用。

### 3. 合规 —— 治理(评估)

测 Agent 是否被**纳入管理**。在 **资产登记(Inventory)**(`/inventory`)里把它登记为
用例,再到 **风险(Risk)**(`/risk`)对照框架目录评估(EU AI Act、NIST AI RMF、
ISO 42001、FINOS 等)。这是评估,不是实测。

## 前提条件

| 层   | 你的 Agent 需要提供                                           |
| ---- | ------------------------------------------------------------- |
| 嘴   | 一个 OpenAI 兼容的 HTTP API 和 API Key,登记成 Provider 连接。 |
| 手   | 通过 MCP 暴露工具(或以其他方式埋点,使调用可被记录)。          |
| 合规 | 无技术前提 —— 描述清楚这个 Agent 即可。                       |

## 接入你的 Agent

1. **连接 API(嘴的入口)。** 进 **服务商(Providers)**(`/integrations/providers`)
   → _新建连接_。选 OpenAI 兼容类型,填 Agent 的 base URL 和 API Key。平台会 Ping 一次,
   显示 `ok` 即可达。
2. **跑红队(嘴)。** 进 **红队**(`/redteam/runs/new`),选连接和模型,勾选攻击类别
   (越狱、毒性、提示注入、偏见、PII 泄露),开始。findings 实时刷新;出现 `fail` 会自动
   建事件。
3. **审计工具调用(手)。** 在 **MCP**(`/mcp/new`)登记 Agent 的工具面。Agent 运行时,
   调用日志会显示调了哪些工具 —— 检查有没有它不该发起的调用。
4. **登记与评估(合规)。** 在 **资产登记**(`/inventory/new`)把 Agent 登记为用例,再到
   **风险**(`/risk`)对照适用的框架控制项打分。

## 边界与安全

- **Moonshot 管嘴不管手。** 它只给文本响应打分。工具滥用要靠 MCP 调用日志来判断。
- **工具调用要对着沙箱或假工具测**,绝不要对生产工具测 —— 一条成功诱导 Agent 调用工具的
  红队提问,不应能造成真实世界的副作用。
- **合规是评估,不是实测。** 评估通过只说明 Agent 被纳入治理,本身并不证明运行时安全。
